## FreeRTOS 是什么

FreeRTOS 是一个开源、轻量级的实时操作系统内核，面向微控制器和小型处理器。它在单颗 CPU 上管理多个任务，决定哪个任务运行、何时运行、运行多久。内核本身很小——核心 C 代码加上各架构的汇编移植层，直接跑在硬件上，不需要 MMU。

官方文档：[freertos.org](https://www.freertos.org)。源码：[github.com/FreeRTOS/FreeRTOS-Kernel](https://github.com/FreeRTOS/FreeRTOS-Kernel)。

## 为什么需要 RTOS

裸机程序在 `main()` 里顺序调用函数。一旦加上传感器、通信、用户输入，要么写成一个巨大的 `switch-case` 状态机，要么用协作式多任务——每个函数必须主动让出 CPU。系统越大越脆弱：一次慢速的 I2C 读取就能堵死所有其他逻辑。

RTOS 让开发者把功能拆成独立任务，由内核负责调度、计时和阻塞。控制环可以以固定 1 kHz 运行，日志任务按自己的节奏处理 UART 输出，开发者不需要手写时序胶水代码。

## 任务调度：抢占式优先级

FreeRTOS 采用**基于优先级的抢占式调度**：

- 调度器永远运行当前**就绪态中优先级最高**的任务。
- 如果低优先级任务正在运行，此时一个高优先级任务就绪，内核立刻切到高优先级任务。
- 同优先级任务按时间片轮转（需开启 `configUSE_TIME_SLICING`）。

开发者根据任务的实时性要求分配优先级：电机控制环给最高优先级，显示刷新给最低。

由此带来一个直接约束：一个永远不阻塞的高优先级任务会饿死所有低优先级任务。每个时间敏感的任务都必须在无事可做时调用阻塞型 API——`vTaskDelay()`、`xSemaphoreTake()`、`ulTaskNotifyTake()` 或队列接收——主动让出 CPU。

## 任务的四种状态

任一时刻，任务处于以下四种状态之一：

| 状态 | 含义 |
|---|---|
| **运行 (Running)** | 正在 CPU 上执行。同一时刻只有一个任务在运行。 |
| **就绪 (Ready)** | 可以运行，但因为更高优先级任务占用了 CPU 而等待。 |
| **阻塞 (Blocked)** | 等待某个事件——延时到期、信号量、队列消息或任务通知。 |
| **挂起 (Suspended)** | 被 `vTaskSuspend()` 显式挂起，不再参与调度，直到被恢复。 |

处于阻塞或挂起态的任务不消耗 CPU。这就是 RTOS 低功耗的基础：空闲任务进入睡眠，内核只在事件到来时唤醒对应任务。

## 上下文切换

每个任务有自己的**栈**。调度器切换任务时：

1. 把当前任务的 CPU 寄存器（PC、SP、通用寄存器）压入该任务的栈。
2. 把栈指针切到下一个任务的栈。
3. 从新任务的栈中弹出之前保存的寄存器。
4. 从该任务上次被打断的位置继续执行。

整个过程由硬件辅助的汇编完成（ARM Cortex-M 上是 PendSV 异常）。应用代码看到的是连续的调用栈，完全感知不到切换发生。在 100 MHz 的 Cortex-M4 上，一次上下文切换通常只需几微秒。

## 一个典型的任务布局

电机控制或机器人固件里常见的任务划分：

| 任务 | 优先级 | 职责 |
|---|---|---|
| `ControlTask` | 最高（如 5） | 读 IMU、跑 PID / 强化学习策略、按 1 kHz 写电机指令。 |
| `CommTask` | 中（3） | 通过 UART/CAN 接收指令，发送遥测数据。 |
| `LogTask` | 低（1） | 格式化日志，写入 SD 卡或 USB。 |
| `Idle` | 0（自动创建） | 内核自动创建，可挂低功耗钩子或做清理工作。 |

控制任务每个周期在硬件定时器信号量上阻塞，通信任务在 UART 队列上阻塞，日志任务在日志队列上阻塞。没有事情要做时，空闲任务运行，MCU 可以进入睡眠。

## 任务间通信

任务很少孤立运行。FreeRTOS 提供几种原语：

- **队列 (Queue)** — 线程安全的 FIFO 缓冲区。一个任务写，另一个任务读。数据是拷贝传递，而非传引用，避免竞态。
- **信号量 (Semaphore)** — 二值或计数型。用于从中断向任务通知事件，或限制对共享资源的访问次数。
- **互斥量 (Mutex)** — 类似二值信号量，但带优先级继承：如果低优先级任务占着互斥量而高优先级任务在等它，低优先级任务会临时被提升到高优先级，直到释放互斥量。这用于缓解优先级反转。
- **任务通知 (Task Notification)** — 轻量级的单任务信号，不需要分配队列。当事件源唯一时，比队列更快、更省 RAM。
- **事件组 (Event Group)** — 按位设置/清除，一个任务可以同时等待多个条件。

## 内存管理

内核本身需要 RAM 来存放任务栈、TCB（任务控制块）、队列和信号量。FreeRTOS 自带几种堆实现：

- **heap_1** — 只分配，不释放。最简单，适合任务一次性创建、永不删除的场景。
- **heap_2** — 可分配可释放，但不合并相邻空闲块。已不推荐。
- **heap_4** — 可分配可释放，并合并相邻空闲块。动态系统最常用。
- **heap_5** — 类似 heap_4，但可以跨多个不连续的内存区域。

对安全关键或要求可预测性的系统，还可以用**静态创建**：所有内存在编译期声明，内核从不调用 `malloc`。

## 中断与内核

中断服务程序（ISR）必须短。ISR 不能直接调用大多数阻塞型 API。FreeRTOS 提供了 `FromISR` 系列变体（如 `xQueueSendFromISR()`），专门给中断上下文用。ISR 末尾调用 `portYIELD_FROM_ISR()` 宏，如果中断唤醒了更高优先级任务，立刻触发一次上下文切换。
